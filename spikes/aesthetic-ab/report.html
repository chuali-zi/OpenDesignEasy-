打样房 Proof Room

OEYdesign 的核心动作是「产出可交付物 + 对象级反馈 + 版本」，这与印刷打样房的心智完全同构：一张大台面上摊开校样，旁边是批注单。所以整个界面按「校样台」来做——纸面底色、印刷规矩线、批注红，让「预览」看起来像一张正在被打样的实物，而不是一个 dashboard。版本被当作批次号对待，而不是设置里的一个字符串。

标题字体"Newsreader", "Source Han Serif SC", Georgia, serif
正文字体"IBM Plex Mono", "SF Mono", "Noto Sans Mono CJK SC", monospace
字号阶[11, 13, 15, 18, 24, 40, 96]
间距阶[4, 8, 12, 20, 32, 56, 96]
版式原型批注单 + 校样台：左栏固定 340px 窄批注单（对话），右栏通吃剩余宽度做校样台，预览物居中悬浮于纸面上，四周留白不少于 56px；全界面用 1px 实线分隔，无圆角无卡片阴影，靠线、留白和字阶分区而不是靠容器套容器。
不常见的颜色关系暖纸底 #F2EFE6 与工业安全橙红 #E8490F 的搭配。常规做法会用蓝或紫去配中性底求「科技感」；这里反用印刷车间的红笔逻辑，成立的原因是：强调色的语义就是「人对产物做的记号」，它和纸面天然属于同一个物理场景，比任何数字感的蓝都更贴合「对象级反馈」这个产品行为。
刻意的反常动作：当前版本号（如 v3）以 96px 衬线字、作为一枚「批次章」压在预览区右上角，颜色用批注红 #E8490F，透明度 100%，不换行不缩小；旁边竖排等宽小字标注该版本的时间戳与变更对象数。
为什么成立：版本是这个产品的一等行为（可回滚、可对比、可导出），但几乎所有同类工具都把它塞进下拉框。把它放大成打样批次章，是把信息层级对齐到产品真实价值上：用户回到工作台第一眼就该知道「我现在看的是哪一版」。它成立还因为语义自洽——打样稿上本来就有批次章，这不是装饰，是借用了一个真实存在的物件。
明确禁止：
  • 禁止任何渐变与玻璃拟态——纸面和红笔没有渐变
  • 禁止圆角大于 2px，禁止卡片阴影堆叠分区——分区只用 1px 规矩线和留白
  • 禁止蓝紫色系强调色——那是协作工具的默认肤色，会立刻稀释打样房语义
  • 禁止把对话栏做成聊天气泡流——它是批注单，用户与 agent 的发言用左边线 + 角色标签区分，不用左右气泡

校对台 Proofing Table

OEYdesign 的本质是「人下指令、机器交稿、人批改」的循环，这个循环在物理世界的原型就是编辑的校对台：一张暖白纸、黑墨、一支红笔。把界面做成校对台而不是「科技深色舱」，能让版本、批注、导出这些核心动作获得天然的视觉语义（红=批改痕迹），也让 AI 产品少见地显得克制可信。

标题字体Fraunces, 'Iowan Old Style', 'Palatino Linotype', Georgia, serif
正文字体'IBM Plex Mono', 'SF Mono', 'Cascadia Mono', Menlo, monospace
字号阶[11, 13, 15, 20, 28, 44, 96]
间距阶[4, 8, 12, 20, 32, 56]
版式原型24/76 校对台：左侧对话栏固定 340px 窄条，右侧预览区吃掉其余全部宽度并上下通顶；两栏之间只有一根 1px 硬分隔线，没有任何卡片嵌套、没有悬浮面板，所有区块用 hairline 横线切分，对齐全部贴线不贴圆角容器。
不常见的颜色关系朱红压在暖米纸上。红色在 UI 惯例里几乎只等于错误/危险，这里它被重新指派为「人工批注」的意思——像在稿纸上用红笔圈改，成立的原因是整个环境（纸色底、黑墨字、零圆角）都在暗示这是一张可被批改的稿子，而不是一块屏幕。
刻意的反常动作：预览区左上角的版本号做成 96px 的衬线巨字「v3」，压在预览画布的边缘线上，旁边配 11px 等宽大写小标签（STATUS: DRAFT · 2 PENDING MARKS）；同时对话栏的标题被故意缩成 11px 小字，对话正文反而是 15px。
为什么成立：版本是这个产品唯一真正重要的状态——用户所有的焦虑都来自「我改的是哪一版、导出的是哪一版」。把版本号放大到印章尺度，等于在每张稿子上盖一个骑缝章，它不可误读、不可忽略；而界面标题缩成小字，是因为「工作台叫什么」从来不是用户要找的信息。这不是装饰性大字，是信息优先级的如实呈现。
明确禁止：
  • 禁止任何圆角大于 2px，禁止卡片套卡片——稿纸没有圆角
  • 禁止渐变、毛玻璃、投影，层次只允许靠 1px hairline 和留白
  • 禁止蓝/紫系强调色，朱红 #E03E12 是全页唯一高饱和色
  • 禁止把 agent 消息做成气泡——对话是校对记录，左右通栏排，不用聊天气泡 UI
