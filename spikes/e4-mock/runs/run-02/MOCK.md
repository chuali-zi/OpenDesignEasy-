# MOCK.md —— Mock 行为声明

本文件如实声明「Nexus · Agent 工作台」静态原型中**所有** mock（伪造）行为。本项目没有任何真实后端、不发起任何真实网络请求，所有数据与交互响应均在前端伪造。

## 一、总体技术手段

| 技术手段 | 用途 | 位置 |
|---|---|---|
| 内联数组（假数据） | 4 个种子项目的名称、描述、初始消息、初始产出 | `app.js` 中 `SEED_PROJECTS` |
| `setTimeout` + `Promise` 模拟网络延迟 | 所有接口返回前延迟 250~700ms（随机），并在顶栏显示「mock 请求中」状态 | `app.js` 中 `delay()`、`LATENCY_MIN/MAX` |
| `window.__mockApi__` 假客户端 | 对外暴露 4 个假接口，UI 层只通过它取数 | `app.js` 中 `mockApi` |
| 规则推导引擎 | 根据用户输入文本的关键词，按固定规则生成 agent 回复与预览产出 | `app.js` 中 `deriveReply()` |

未使用的手段（声明以排除歧义）：**没有**拦截/覆盖 `fetch` 或 `XMLHttpRequest`，**没有**注册 Service Worker，**没有**使用 `localStorage` 持久化（刷新页面后，运行期新建的项目和新增消息会丢失，恢复为种子数据）。

## 二、Mock 接口清单（`window.__mockApi__`）

### 1. `listProjects()` —— 项目列表
- **数据来源**：纯虚构编造的 4 个种子项目（官网重构助手 / 周报撰写助手 / 数据分析助手 / 新会话·未命名），以及运行期通过 `createProject()` 追加的项目。所有名称、描述、颜色、状态均为作者编造。
- **延迟**：`setTimeout` 随机 250~700ms。

### 2. `openProject(id)` —— 打开/切换项目
- **数据来源**：从内联数组中按 id 查找，返回该项目的完整消息记录与产出（深拷贝）。副作用：把该项目状态改为「进行中」。
- **延迟**：同上。

### 3. `createProject()` —— 新建项目
- **数据来源**：规则推导 + 虚构。项目名按「新会话 · N」编号（N 为运行期已建数量 +1），欢迎语为固定模板文本，新建项目无产出（预览区显示空态）。
- **延迟**：同上。

### 4. `sendMessage(projectId, userText)` —— 发送消息并生成回复
- **技术手段**：先把用户消息追加到项目消息数组，再调用规则推导引擎 `deriveReply()` 生成 agent 回复与（可选的）预览产出，写回项目后返回。
- **延迟**：同上（此延迟在 UI 上表现为「agent 正在组织回复…」的打字指示器）。

## 三、回复与预览产出的推导规则（`deriveReply()`）

回复**不是**预写死的固定文案，而是按以下规则从用户输入推导：

设 `seed = 用户输入字符数 + 当前消息总数`（用于伪随机取模）。

1. **代码型**：输入匹配 `代码|code|函数|接口|脚本`（不区分大小写）
   - 回复文本：从 2 条模板中按 `seed` 取模选 1 条，模板中嵌入生成代码的行数；
   - 预览产出：代码卡片。函数名 = `task_<消息数>`，函数体占位行数 = `2 + (seed % 4)`（即 2~5 行），首行注释截取用户输入前 24 字。
2. **报告型**：输入含 `总结|报告|周报|汇总|复盘`
   - 把用户输入按标点/空格分词，取长度 ≥2 的前 3 个词作为关键词；
   - 回复文本：固定句式，嵌入关键词；
   - 预览产出：报告卡片。三段正文由关键词拼接模板生成，其中「亮点」的百分比 = `3 + seed % 15`；顶部 3 个统计格的值分别 = 关键词数、版本号 `v<消息数>`、`1 + seed % 3`。
3. **表格型**：输入含 `表格|数据|统计|对比|清单`
   - 用户输入分词取前 4 个词作为表格行（每行一个「维度」）；
   - 每行的「量级 / 占比 / 环比」三列数值由 `seed` 与行号的取模运算生成（伪随机占位，非真实数据）；
   - 回复文本：固定句式，嵌入行数。
4. **兜底型**：以上都不命中
   - 从 3 条模板中按 `seed` 取模选 1 条纯文本回复（其中一条嵌入消息序号）；
   - **不更新**预览区。

未命中规则时预览区保持不变，这是有意设计（模拟「讨论型消息不产生交付物」）。

## 四、各交互点与数据的对应关系

| 界面交互 | 触发的 mock | 数据性质 |
|---|---|---|
| 首次加载项目列表 | `listProjects()` | 纯虚构内联数据 |
| 点击项目切换上下文 | `openProject(id)` | 纯虚构内联数据（初始消息、初始产出均为编造） |
| 点击「＋ 新建」 | `createProject()` + `openProject()` | 模板编号 + 固定欢迎语（规则推导） |
| 发送消息 | `sendMessage()` | 回复与产出按第三节规则从输入推导；种子项目的初始消息为纯虚构 |
| 预览区初始内容 | 随 `openProject()` 返回 | 3 个种子项目的产出（代码骨架 / 周报草稿 / 渠道表格）均为纯虚构编造，其中表格内数字、周报百分比为占位假数据 |
| 预览区随对话更新 | 随 `sendMessage()` 返回 | 规则推导生成，数值为取模运算的伪随机占位 |
| 顶栏「mock 链路正常 / 请求中」 | UI 层根据 Promise 状态切换 | 仅为视觉状态，不代表真实网络 |
| 打字指示器「agent 正在组织回复…」 | `sendMessage()` 延迟期间显示 | 纯视觉模拟 |

## 五、覆盖率声明

以上清单覆盖了代码中实际存在的全部 mock 行为：`app.js` 内不存在任何真实网络请求、不存在未声明的数据来源；`index.html` 与 `styles.css` 不含任何外部资源引用（无外链字体、图标、图片、脚本、样式）。打开 `index.html` 即可离线运行全部交互。
