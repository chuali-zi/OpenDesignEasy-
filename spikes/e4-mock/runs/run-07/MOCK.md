# MOCK.md —— Nexus 工作台 mock 行为声明

本项目为纯静态前端原型，**没有任何真实后端，也不发起任何网络请求**（无 CDN、无外部字体/图标/图片）。以下如实列出代码中所有 mock 行为。

## 一、技术手段总览

| 手段 | 是否使用 | 说明 |
|---|---|---|
| 内联假数据（JS 数组/对象） | ✅ | 项目种子数据、初始会话、组件模板均硬编码在 `app.js` |
| `setTimeout` 模拟网络延迟 | ✅ | 统一封装为 `delay(min, max)`，所有 mock 接口都经它返回 Promise |
| 规则/模板推导生成内容 | ✅ | agent 回复与预览产物由关键词规则 + HTML 模板拼装生成（见下文） |
| 暴露 `window.__mockApi__` 假客户端 | ✅ | 界面代码只通过该客户端取数，模拟真实 API 分层 |
| fetch / XMLHttpRequest 拦截 | ❌ | 未使用 |
| Service Worker | ❌ | 未使用 |
| localStorage / 任何持久化 | ❌ | 未使用，**刷新页面后所有状态重置为种子数据** |

## 二、被 mock 的接口 / 交互点

均挂在 `window.__mockApi__` 上，位于 `app.js`：

### 1. 项目列表 —— `MockAPI.listProjects()`
- **行为**：返回项目摘要数组（id / 名称 / 描述 / 更新时间），延迟 200~500ms。
- **数据来源**：**纯虚构**。4 个种子项目（官网落地页 / 数据看板 / 活动报名页 / 个人博客）由 `seedProject()` 硬编码构造，与任何真实产品无关。

### 2. 项目详情（切换项目）—— `MockAPI.getProject(id)`
- **行为**：返回该项目的完整会话记录 + 当前产物 HTML + 版本号，延迟 300~700ms。点击侧边栏项目项即触发，对话区与预览区随之整体替换。
- **数据来源**：会话为**虚构的**预置对话（每项目 1 条用户消息 + 1 条 agent 消息）；产物 HTML 为**规则推导**（见第 4 点）。

### 3. 发送消息后的 agent 回复 —— `MockAPI.sendMessage(id, text)`
- **行为**：延迟 700~1600ms（模拟"思考"），期间界面显示"agent 正在思考…"占位气泡；返回回复文本、是否变更产物、新版本号与（如有变更的）新产物 HTML。
- **数据来源**：**规则推导**，不是真模型。规则如下（按用户输入的关键词命中，见 `generateReply()`）：

  | 输入命中关键词 | 推导结果 |
  |---|---|
  | 蓝/红/绿/紫/橙 + “颜色/主题/配色”等 | 修改产物主题色（accent），版本 +1 |
  | “按钮 / button” | 追加按钮组件，版本 +1 |
  | “表格 / 数据 / table” | 追加数据表格组件，版本 +1 |
  | “表单 / 报名 / 输入框 / form” | 追加报名表单组件，版本 +1 |
  | “卡片 / 介绍 / 特性 / card” | 追加介绍卡片组件，版本 +1 |
  | “引用 / 标语 / slogan” | 追加引用文案组件（文案取用户消息去除指令词后的剩余文本，做 HTML 转义后嵌入），版本 +1 |
  | 全部未命中 | 从 3 条预置"闲聊/引导"回复模板中**随机选 1 条**，产物不变 |

  回复正文本身也是**模板拼装**：列出本次变更项 + 当前版本号。

### 4. 预览产物 —— `renderArtifact(project)`
- **行为**：预览区用 `<iframe srcdoc="...">` 渲染一份完整 HTML 文档；切换项目或产物版本更新时重新生成并替换。
- **数据来源**：**规则推导**。产物 = 基础 HTML/CSS 模板（内联样式，硬编码于 `renderArtifact`）+ 项目当前的组件数组（`project.components`）按序拼装 + 主题色变量。组件的 HTML 片段来自硬编码的 `COMPONENT_BUILDERS` 模板（hero / card / button / table / form / quote）。表格里的数字、表单字段、按钮文案均为**虚构**。
- **注意**：iframe 设置了 `sandbox` 且内容完全由本地字符串生成，不加载任何外部资源。

### 5. 新建项目 —— `MockAPI.createProject()`
- **行为**：延迟 300~600ms，向项目列表头部插入一个新项目并自动选中。
- **数据来源**：**规则推导**。名称按计数器生成（"未命名项目 N"），产物为仅含 hero 的空白模板，会话含 1 条固定的 agent 欢迎语（模板文案）。

### 6. 界面中的"加载/生成中"状态
- 项目切换时的"加载中…"、发消息时的"agent 生成中…"与打字占位气泡，均对应上述 `setTimeout` 延迟窗口，属于模拟体验的一部分，不代表真实计算。

## 三、遗漏自查

- 代码中**没有**任何 `fetch` / `XMLHttpRequest` / `WebSocket` / `EventSource` 调用。
- 代码中**没有**任何外部 URL（http/https 协议资源引用为零）。
- 所有会变化的内容（列表、会话、预览、版本号）均由上文第 1~5 点覆盖，无其他隐藏 mock 行为。
