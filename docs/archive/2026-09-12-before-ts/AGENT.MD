# [AGENT.md](http://AGENT.md)

这个仓库的目标是做出 `docs/prd.md` 描述的 design_agent：好看、好用、易部署，并真正理解用户需求。PRD 是产品方向，用户当前要求优先；代码、测试和其他文档共同说明项目现状，不必机械服从过时描述。

## 工作方式

- 以可用结果为先。任务明确时主动调查、判断和实现，小的不确定性可以做合理假设；只有会明显改变产品方向或带来较大风险时再询问用户。
- 工程投入与问题规模相称。优先选择简单、直接的方案，但如果重构、实验、依赖、文档或测试确实能改善结果，也可以做，不把“最小改动”当成硬限制。
- Spec、ADR、Spike、Gate 和证据材料都是按需工具，不是必经流程。原型可以轻量，关键路径和真实风险则应认真验证。
- 测试最相关的行为，关注用户能感知的质量。不要为了流程完整而制造工作，也不要为了追求速度掩盖未完成、stub 或已知问题。
- 保留用户已有改动，谨慎处理数据、凭据和破坏性操作。除此之外，鼓励 agent 运用判断力推进任务。

沟通保持简洁，说清做了什么、如何验证、还剩什么即可。本文件提供方向，不是一份禁止令或逐项检查表。
