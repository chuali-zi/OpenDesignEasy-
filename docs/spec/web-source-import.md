# Web 源码项目导入与往返边界

2026-10-13，R4 的首个工程导入切片。沿全 TypeScript/Pi/统一文档主线实现；不是任意 HTML 或第三方 React 工程的无损转换。

## 可完成的用户路径

在 OEY 导出 `source.zip`，在外部修改受管 TS/TSX/CSS 模块，再在工作台点击“导入源码”，选择 ZIP。返回的是一个新的可编辑 Web 文档：页面/路由、断点、原生节点、组件绑定、公开 props 与图片原件保留；模块内容以 ZIP 中的文件为准，并报告哪些模块与快照不同。用户可继续修改原生对象、撤销/重做、重开项目，再导出和再次导入。原文档和原历史不覆盖。

CLI 不需要 Web host：

```sh
npm run oey -- document import-source .tmp/project site.source.zip --name "Returned website"
```

Web host 使用 `POST /api/documents/import-source`，请求 `{base64, name?}`，返回 `{document, source, changedModules, warnings}`。导入需要同机/已允许 origin，沿用 host 的来源保护。每次成功导入创建独立 documentId 和 revision0；不重放外部历史或模型请求。

## 支持范围

- 必须包含有效且互相一致的 `oey-document.json` 和 `oey-metadata.json`（format 为 web-source）。原生编辑结构以快照为真源，验证页路由、节点树、模块绑定与资产元数据。
- 快照声明的受管模块可以在外部修改；本轮依赖支持 React/React DOM 和包内已声明的相对 TS/TSX/CSS 模块。源码按文本保存，不执行。相对模块不能越界，动态计算 import、CommonJS require、文件系统 glob 宏与未声明依赖拒绝。
- 自动生成的 `src/App.tsx`、`src/main.tsx`、`src/style.css`、`index.html` 必须与快照投影一致。外部改动这些文件时明确拒绝，不把丢失语义的源码冒充完整可编辑原生结构；可改受管模块，或回到 OEY 修改原生对象。
- 图片原件验证类型与尺寸后重新分配资产 ID，原生节点引用同步绑定。新源码导出连未使用的已登记图片也打包；旧导出包缺少未使用图片时明确报告省略，引用中的图片缺失则拒绝。任意源码里的字面量资产 URL 与 CSS 文件 URL 尚未往返映射，导入时拒绝，优先使用原生图片节点或 CSS 内嵌 data。
- `package.json` 和 `vite.config.ts` 可保留在输入包中，但安装脚本/自定义构建配置不执行，也不采纳；未来显式构建仍使用已有固定配置和已安装依赖。未知文件、额外依赖、外部/public 任意文件暂不支持。
- 普通 HTML、静态 ZIP、生产 build.zip、没有 OEY 快照的 React/Vite 项目会明确拒绝，不能据此宣布一般工程导入完成。

## 安全与持久化

输入 ZIP 至多8 MiB，256条目，单文件展开至多4 MiB，总展开至多16 MiB。仅接受单卷普通ZIP、STORE/DEFLATE；不支持ZIP64、加密或符号链接。先检查中央目录、原始文件名/本地头一致性、相对路径、重复名称、重叠区间和大小；实际解压另有输出硬上限，核对CRC与实际长度。拒绝路径穿越、绝对/驱动器路径、隐藏文件（包括环境/凭据文件）与未知包内容。

全程内存读取，不把 ZIP 路径解压到文件系统，不跟随链接，不运行模块/配置/HTML，不联网安装依赖，不读取机器凭据。快照限制64页、2000节点、128模块，限制JSON/树深度，禁止污染原型的JSON键。所有内容与图片先验证，再以随机资产文件名写入当前项目；文档与资产记录在同一SQLite事务提交，失败清理本次资产文件。导入 provenance 和 document.changed 事件持久化，人机仍共用同一个 runtime。

导入后的源码在用户显式“运行应用”时才进入既有固定 Vite 构建及隔离 iframe；导入本身不执行它。此边界不承诺任意第三方插件、自定义构建系统或包管理脚本。
