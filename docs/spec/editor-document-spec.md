# 编辑文档与人机同步规范

> TS 重构 v1，2026-09-12；状态更新 2026-09-26。Deck 编辑已通过 R2/R3 验收；Web 文档与命令在 R4 实施，Doc 编辑待 R5。本文中的完整直接编辑范围仍是必做要求。
> 本文定义 Document Kernel 与图形编辑器的共同约定；命令信封见 [系统规范](system-spec.md)。

## 1. 产品体验与权威状态

用户可以像使用设计工具一样选择、拖拽、调整尺寸、旋转、编辑文字、管理图层，并在同一作品中继续与 agent 对话。人工与 agent 修改操作同一份结构化文档。聊天、HTML、Canvas 内部对象和截图不能各自成为另一份权威状态。

从第一个可编辑对象开始就有稳定 ID、结构和修订。手工修改后，agent 读取的新状态必须包含这些修改；agent 提交后，画布、文本、图层、属性与其他客户端同步更新。

Figma 式指本规范列出的直接编辑能力，不要求复制 Figma 全部插件、多人服务或所有交互细节。

## 2. 文档模型

共同头部包括 schemaVersion、documentId、kind、revision、名称、资产引用和设计约束。内容使用明确的联合类型：

| 文档类型 | 权威结构 | 布局语义 |
|---|---|---|
| DeckDocument | 页面、主题、对象树；文本、图片、形状、组、表格和图表 | 固定尺寸页面，父级局部坐标与变换 |
| WebDocument | 页面/路由、组件树、样式、断点、受管代码模块及实例绑定 | DOM 语义、flow/flex/grid 和明确的定位 |
| DocDocument | ProseMirror 正文结构、章节、样式、页面参数、行内及浮动对象 | 正文流、分页规则与锚点 |

共享对象身份、样式基础、文本内容表示和操作机制，不强迫三种媒介使用相同的定位规则。Canvas 库的序列化 JSON 不能作为产品保存格式。

节点 ID 在重命名、排序、重绘、模型切换与保存重开后保持稳定。复制产生新 ID，并重写内部引用。分组、导入与媒介转换记录来源映射，不能按当前数组下标识别对象。

## 3. 坐标、缩放与布局

Deck 采用固定页面逻辑单位，记录单位与页面尺寸，导出时统一换算到 PPTX 使用单位。位置与尺寸属于父级坐标；旋转与父子矩阵转换有唯一实现。

必须区分三类操作：

- viewport zoom/pan：客户端视口变化，不修改文档，不进入撤销。
- object resize：改变对象几何尺寸及适用的约束；文字框变大默认不会等比例放大字体。
- explicit scale：按用户明确选择缩放组及其内部样式；与普通调整框尺寸分开。

Konva Transformer 等视图库产生的 scale 先转换为文档语义，再提交；不能把未归一化的临时 transform 当作最终对象。多选旋转、组内移动、缩放后的命中与参考线都使用同一坐标计算。

Web 的流式元素拖动主要改变顺序、容器或 grid 位置。自由定位对象修改对应定位属性；在两类布局间切换要明确更新布局模式，不能无声把整站改成绝对定位。

Doc 的段落拖动是正文重排，浮动图片拖动更新锚点和偏移，正文缩放不能以改变整页 CSS transform 来冒充排版。分页是布局结果，显式分页符和章节参数才属于持久内容。

## 4. 必须实现的图形操作

| 类别 | 完整要求 |
|---|---|
| 选择 | 单选、多选、框选、组内选择、层级定位、键盘切换 |
| 视口 | 平移、滚轮/手势缩放、适应页面、中心定位 |
| 几何 | 移动、调整尺寸、旋转、比例保持、坐标/尺寸字段输入 |
| 层级 | 新建/复制/删除、排序、分组/解组、父级变更、隐藏/锁定 |
| 排列 | 对齐、均匀分布、网格/对象吸附、参考线；关闭吸附时自由移动 |
| 文本 | 直接输入、选择、字体/字号/颜色/字重/行距/段落样式；中文 IME |
| 图像 | 替换、裁切、适配/填充、透明度，保留原始资产 |
| 样式 | 填充、描边、圆角等适用属性，多选时显示混合值 |
| 历史 | 撤销/重做、版本保存与恢复，人机操作同一历史 |
| 输入方式 | 快捷键、删除/复制粘贴、属性面板，与拖拽共用语义 |

表格、图表、Web 组件和文档正文应有与其内容对应的编辑方式。复杂对象可以专用面板编辑数据，不能仅把它们做成可拖动截图。

## 5. 统一操作

初始操作族覆盖 document/page/section 创建、node.insert/remove/reparent/reorder、geometry.update、style.update、text.apply、asset.replace、table.update、chart.update、web.layout.update 和 source.update。具体字段由对应媒介 schema 约束，不以不受限 JSON Patch 暴露内部存储。

一个用户手势从开始到结束只提交一个命令；拖动期间连续帧是本地预演。长篇文字输入可按连续输入和停顿合并历史，但保留正确 IME composition 边界。

Agent 的 document.apply 工具提交相同操作。模型流出的半截 JSON 和参数预览不能进入文档；一批参数完整、校验通过才提交。长任务通过小而完整的操作批次展示进度。

编辑器可以复用 Kernel 做乐观计算，最终结果以 runtime 提交为准。冲突或取消时丢弃预演，加载当前对象并解释原因，不能让 UI 长期展示未保存状态。

## 6. 人工和 agent 冲突

baseRevision 是读取起点，前置条件指出操作真正依赖的状态。不能只检查全局修订不相等就拒绝一切，也不能忽略修订进行最后写入覆盖。

修改已有节点时，命令必须携带所改属性/结构的基准值，或指向 runtime 可读取的基准快照。Kernel 根据操作补足结构依赖并检查条件是否完整；缺少必要条件就拒绝，不能以空 preconditions 绕过冲突处理。

具体规则：

- Agent 改图片说明，用户只改图片位置：在相关前置条件仍成立时可重放。
- 两者都改同一位置、颜色、布局属性或文本范围：返回冲突与当前值。
- 删除/替换子树：检查目标及相关后代是否被修改，防止删除用户刚添加的文字。
- 重新挂到父级、排序和分组：校验父关系、邻接关系与必要的坐标依赖；用户在别处改文案不必冲突。
- 文本使用 ProseMirror step 与位置映射；无法可靠映射时返回冲突，不能覆盖整段来逃避映射。
- 锁定对象不能被模型常规操作修改。用户明确要求解锁时先提交显式解锁操作。

Kernel 实现重放与校验，模型不负责计算并发正确性。冲突是可恢复工具结果，agent 重读相关子树再决定修改。一个 run 不因收到普通人工命令就被强行取消。

若用户正在未提交的拖拽中收到 agent 提交，本地预演基于新状态重新校验；同属性变化时结束该预演并提示，不发送旧的放手位置覆盖新提交。文字编辑同理处理远端 transaction。

## 7. 撤销、重做与版本

第一版采用**统一线性文档历史**：撤销最近一次可撤销的已提交操作，无论来自用户还是 agent。界面明确显示操作人和摘要，避免把“撤销”误解成只撤销手工动作。

一次手势、一批 agent 编辑分别形成历史项。反向操作保存修改所需旧值或子树；撤销也经过 Kernel，并产生新的修订与广播。历史游标与 redo 栈单独维护，撤销命令不能无限作为普通新编辑压入自身历史。

新编辑使原 redo 分支失效。外部副作用、模型费用和对话不会被文档撤销逆转。移除图片引用不立即物理删除资产，历史仍可恢复它。

用户版本是可查看和恢复的完整设计快照。恢复版本产生新修订并保留原历史记录；Pi 会话分支不是设计版本，也不隐式回退画布。

## 8. Web 源码与可视编辑的边界

OEY 原生组件的结构、属性、样式和布局在 WebDocument 内；渲染器生成实际 DOM，使用稳定节点映射定位，编辑 overlay 覆盖其上。源码生产读取同一模型。

需要自定义 React/逻辑代码时，将 TS/TSX/CSS 模块作为文档管理的源码资产，并记录组件导出、实例和可编辑 props/bounds。源码修改通过 source.update 写入版本，再构建；不能让 agent 任意改构建目录，使视觉文档失真。

原生节点可以完整可视编辑。自定义组件整体可以移动、调整布局与公开属性；其内部只有建立可靠映射后才可直接编辑。应清楚显示当前支持范围，不能把所有模型生成内容塞进一个不透明组件以规避直接编辑。

导入任意现有 React/CSS 工程不承诺自动无损转换。支持结构导入的部分进入模型；其余保留受管源码和明确的组件边界。继续编码与可视操作仍经过同一个版本入口。

## 9. Doc 与富文本

ProseMirror JSON 是 Doc 正文结构的一部分；稳定块 ID、样式引用、锚点与页面规则由 OEY schema 明确。Deck 文本对象可复用富文本内容模型，但保留文本框的独立几何。

文字编辑、agent 文本修订、注入模板内容、DOCX 导出使用同一富文本转换规则。HTML/Markdown 可以导入导出，不能通过反复转换丢失列表、表格、锚点和样式。

字形测量、CJK 字体回退和溢出处理必须在目标平台验证。编辑器分页预览与 Word 渲染可能不同，不能宣称选了富文本库就已有完整 Word 排版引擎。

## 10. 必要验收场景

1. 手动拖动封面图、调整标题框、修改图层顺序；agent 读取这些状态再扩展第二页，保持已调整布局。
2. Agent 改颜色/文案后，画布、属性、图层、CLI 读取和保存重开结果一致。
3. 同属性陈旧操作被拒绝，无关属性修改可合并；删除子树不会吞掉新人工内容。
4. 缩放视口后编辑嵌套组、旋转对象、撤销/重做，再保存及导出，几何不漂移。
5. 中文 IME、文本选区、段落重排、表格编辑，在人工与 agent 往返中保留结构。
6. CLI 建项目，Web 编辑，TUI 改选定节点，Desktop 继续；只存在一份修订历史。

这些场景先用确定性操作验证，再用真实模型检查交互质量；不把模型是否恰好生成正确坐标当作 Kernel 的正确性测试。

## 11. 实现依据

[Konva Transformer](https://konvajs.org/docs/react/Transformer.html)提供图形变换基础，[ProseMirror Guide](https://prosemirror.net/docs/guide/)提供富文本结构和事务基础。对象身份、人机冲突、统一历史与媒介映射仍由 OEY 实现，不能归功于引入任一库即已完成。
