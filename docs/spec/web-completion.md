# Web 验收门槛与接续 R5 Doc

2026-10-13，用户要求持续完成 Web 后进入 Docs。这里的 Docs 是 R5 DocDocument：ProseMirror 正文、章节/样式、表格/图片、模板/分页与 DOCX/PDF 生产，不是只补工程文档。

Web 的完成门槛基于当前 PRD/编辑规范，按可验证用户流程交付。任意第三方 React/CSS 内部无损转换不作为阻塞条件；但不能把未做的既定原生编辑能力说成完成。

| 门槛 | 可验证结果 | 当前状态 |
|---|---|---|
| 统一真源与恢复 | Web/CLI/Agent 共用文档/历史；人工与agent冲突不覆盖；撤销/重做、保存重开、重复命令幂等 | 已通过共同历史、幂等、冲突与跨对象保存/重开回归 |
| 原生选择与层级 | 多选/框选/键盘选择、复制/删除/分组/解组、锁/隐藏/排序；清楚区分组件边界 | 原生定位/流式组与选择/层级通过；自定义组件保持受管源码/props 边界 |
| 几何与布局 | 定位对象拖动/缩放/旋转、组手势、属性操作；flow/flex/grid保留语义；对齐/分布/吸附/视口操作 | 已通过定位/流式组、对齐、Flex/Grid、吸附/视口与二维旋转缩放；复杂变换明确拒绝 |
| 富文本与图像 | 正文可直接编辑、选区格式/字体/字号/段落/IME；图片替换、适配/裁切/透明度保留原件 | 富文本、草稿、图片通过；Chromium 原生中文 composition 验证不在组合期间保存 |
| 支持范围内工程导入/生产 | 页面/路由/组件/props/断点与受管源码；支持结构可编辑，其他部分保留源码并说明边界 | OEY源码往返与有限静态 HTML/JSX 导入通过；保留原源码并拒绝执行/外部依赖 |
| 真实完整用户流程 | 多页导航/表单本地演示/响应式、人工与agent往返、源码与静态/构建产物；异常构建/取消/迟到结果/重复操作可恢复 | 贯穿创建/编辑/保存重开/导入导出/撤销重做与异常输入通过 |

推进顺序：先共享富文本基础与异常草稿恢复，再原生选择/层级/组手势及布局辅助，再有限工程结构导入与完整贯穿验收。每个里程碑执行必要离线/真实浏览器回归并正常同步独立分支，更新本表。模型仍为kimi-for-coding/K2.8，未获新的费用范围前不扩展live。

只有上述门槛实际满足并记录支持/拒绝范围后，才将 Web 标为阶段完成并转入 R5 Doc。源码ZIP仍是产品功能；代码交付走Git，不制作代码压缩包。此前整体视觉方向认可有效，新的显著视觉面板给合成真实截图审核；待审截图不阻塞其他可独立实现的逻辑与回归。
