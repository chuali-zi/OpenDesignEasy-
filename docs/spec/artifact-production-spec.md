# 产物生产与格式规范

> TS 重构 v1，2026-09-12。所有新解析、生成、渲染、导出与数据迁入均走 TS 调用链。
> 三媒介是完整交付范围；库选型是实现基线，不等于格式能力已经完成。

## 1. 生产真源

media 读取指定修订的 Document 和资产，生成可视预览、原生文件与源码。生成文件不反向覆盖设计；外部文件修改需要显式导入，不能同时维护两份互不关联的真源。

每份产物记录 documentId、revision、格式、生成状态、文件位置和适用的能力说明。文档变更后，旧预览与导出标明来源版本。

项目文件、聊天、HTML 和截图各有用途。只有结构化文档及其受管源码是可继续编辑的设计状态。

## 2. TS 生产基线

| 能力 | 实现基线 | 必须补齐的产品逻辑 |
|---|---|---|
| Web | TS/React/Vite、实际 DOM、Playwright | 文档到源码映射、多页、响应式、交互、构建与打包 |
| Deck/PPTX | PptxGenJS | 原生对象映射、文字测量、主题、单位、裁切、图表与字体 |
| Doc/DOCX | docx + TS OOXML 处理 | 富文本/样式/表格映射、模板识别、章节、锚点与分页 |
| PDF/截图 | Playwright、PDF.js；必要的随包原生渲染组件 | 明确源文档、字体、分页、真实交付检查 |
| OOXML 导入 | TS ZIP/XML 读取 | relationships、主题/样式继承、媒体、坐标和内容映射 |
| PDF 资料 | PDF.js | 页文本、位置信息、页图和扫描页识别 |
| OCR | Tesseract.js/WASM | 图像预处理、语言资源、置信度与来源定位 |
| XLSX/CSV | ExcelJS 与 TS 表格处理 | sheet/range、值/公式缓存、样式和事实引用 |

不得调用旧 Python 导出器填补未实现项。第三方原生/WASM 组件允许随包使用，产品安装与运行不能要求 Python。

## 3. Web 生产与直接编辑

支持静态站点和受管 React/Vite 应用，包含多页/路由、断点、实际交互和本地资源。按钮、导航、表单演示等应表现出声明的行为，不能以静态截图声称可运行。

WebDocument 管理原生结构/布局及受管代码模块。编辑器使用实际 DOM 布局与 overlay，构建结果用稳定映射关联节点。可视修改和源码修改均提交文档版本；见 [编辑规范](editor-document-spec.md)。

导出包括可读源码、依赖声明、资源和构建产物，以及相应 ZIP/HTML/PDF。生成站点不夹带 OEY 凭据、聊天日志或编辑控制接口。公开发布单独依据用户指令。

导入既有仓库时，TS 工具识别入口、构建命令、组件与资源；只转换可靠支持的结构，其余保留受管源码边界。不能承诺任意 JSX/CSS 自动无损双向转换。

## 4. Deck 原生对象

Deck 编辑器采用固定画布，导出 PPTX 至少保持以下能力：

| 对象 | 编辑模型 | PPTX 交付 |
|---|---|---|
| 文字 | 可编辑富文本框、段落、样式 | 原生文本框/文本 run |
| 图片 | 原件、位置、裁切与透明度 | 独立图片对象 |
| 基础形状 | 几何、填充、描边、圆角 | 原生形状 |
| 表格 | 单元格内容、行列、样式 | 原生表格 |
| 常用图表 | 数据、系列、轴、图例与样式 | 原生可编辑图表及数据 |
| 组/层级 | 子对象与变换、顺序 | 尽量保留分组；至少保留独立对象和正确几何 |
| 公式/复杂插图 | 公式源或矢量/图形结构 | 支持原生表达时原生，否则明确为独立矢量/图片对象 |

常用图表首版至少覆盖柱状、折线、饼图。特殊效果不支持时提供具体对象的说明；整页栅格化再叠文字不满足原生 PPTX 要求。

导出应统一页面单位、组变换、字体、文本框边距、行距、图片裁切与对象叠放顺序。Konva 当前绘图结果不是可直接传入 PptxGenJS 的权威结构。

公式在 OEY 中保留可修改源与确定性渲染；不能把 PPTX 中的公式图片称为 PowerPoint 可直接编辑公式。真实的格式限制在导出界面展示。

## 5. Doc、模板与 DOCX

DocDocument 支持正文段落、标题样式、列表、表格、行内图片、浮动图形、章节、页眉页脚、页边距和分页符。富文本是编辑真源，不能仅把 Markdown 转为固定字号段落。

DOCX 导出按结构与样式生成对应 OOXML，图片引用、表格边界、编号、章节和锚点都从文档导出。用户编辑文本和表格后仍可正常续排。

模板导入读取命名样式、章节设置、占位位置、表格、页眉页脚、图片和可识别字段。需要保留的未知 OOXML 部件可作为原件附属内容保存，修改其支持的区域；不能通过重新生成一份简单 DOCX 号称保留模板。

docx 的 patchDocument 是可采用的占位替换能力，不等于任意 Word 模板的无损编辑引擎。复杂字段、批注/修订、特殊浮动关系等应逐项标注支持度；用户指定模板所需能力列入该任务的实际交付检查。

编辑器分页与 Word 字体/排版差异是实现风险。需要统一字体资源、文本测量和章节参数，并用实际 DOCX 在目标应用中检查，不以浏览器分页看起来正确代替验证。

## 6. PDF 与真实格式检查

PDF 从指定媒介布局生成；记录来源修订、页面尺寸和字体策略。PDF 不承担可继续编辑的权威状态。

浏览器预览、OEY PDF 和 Office 打开效果可能不同。至少保留三类检查：文档对象正确、导出文件结构正确、实际目标应用打开/渲染正确。

研发可以使用实际 PowerPoint/Word 或受控原生工具验证导出文件；产品普通导出不要求用户安装 Office。若要提供与 Office 文件一致的产品内渲染，应明确选定可分发渲染组件并单独验证，不能把 DOCX/PPTX 库误当渲染器。

PDF 与原生文件无法一致时，显示差异，不将一个格式的成功冒充全部格式成功。

## 7. 资料解析与编辑导入分别处理

“能提取内容供 agent 阅读”不等于“能恢复成所有对象可编辑的设计”。

| 输入 | 资料解析必须具备 | 编辑导入基线 |
|---|---|---|
| PPTX | 文字、页面、主题、媒体、对象几何与缩略表现 | 本规范原生文字/形状/图片/表格/常用图表进入 Deck |
| DOCX | 正文、样式、章节、表格、媒体和模板结构 | 支持的正文/表格/图片/章节/样式进入 Doc |
| PDF | 页文本/位置、页图、扫描页 OCR | 保留页图，明确可提取部分；不承诺任意 PDF 全对象无损还原 |
| 图片 | 尺寸、原件、缩略图、必要 OCR/视觉理解 | 图片节点；不能声称已识别所有图层 |
| XLSX/CSV | sheet/range、表头、数值与格式；不能只返回文件说明 | 导入表格或图表的数据源 |
| Web 源码 | 入口、文件、组件、资源与可运行信息 | 支持结构转模型，其余为受管源码组件 |

OCR 引擎处理图像；扫描 PDF 先由 PDF.js 渲染页面，再交给 OCR。公式与文字识别的不确定部分需要呈现，不能当作确认事实。

XLSX 公式保留公式及可用缓存值；没有计算引擎时不能宣称重算公式。旧二进制 Office 文件、加密文件和复杂插件对象不在自动无损导入承诺中，应给出具体转换或缺失说明。

OEY 自己生成的支持范围内对象，应能保存、重开、导出并再次导入而不丢失主要内容与可编辑语义。外部超范围对象保留原件和来源，不能静默丢弃。

## 8. 资产与图像生产

图片生成通过 TS HTTP/SDK 调用服务，保留提示、模型和资产关系；失败可重试或替换，不伪造成功图片。产品不固定绑定旧 Python Seedream 工具签名。

字体、图片和图标的存储与访问统一；渲染能找到实际字体，导出时明确字体替代行为。远程资源在交付中按需要纳入包，避免用户离开 OEY 后产物丢图。

原件与派生缩略图分开保存。覆盖原件需要明确操作；修改裁切和尺寸不会破坏资产源文件。

## 9. 必要验证与已知难点

采用小而有代表性的夹具：三页 Deck（中英文、裁切图、形状、表格、图表）、多页响应式 Web（真实导航/交互）、带模板样式和跨页表格的 Doc。

检查对象编辑、层级、几何、保存重开、源码构建、原生格式结构及实际打开。再加入复杂案例修复具体问题，不先构建覆盖所有 Office 历史特性的转换平台。

主要风险是 Web 源码与可视结构映射、Word 分页、Office 模板继承、字体和复杂 PPTX 对象。它们是 R4/R5/R7 的明确工作，不能延期成永久 Python 兜底。

## 10. 官方依据

- [PptxGenJS](https://github.com/gitbrent/PptxGenJS)：程序化 PPTX 对象生产；其 HTML 能力不能视为任意网页到原生幻灯片转换。
- [docx](https://docx.js.org/)、[patchDocument](https://docx.js.org/api/functions/patchDocument.html)：DOCX 创建与补丁能力。
- [PDF.js](https://mozilla.github.io/pdf.js/)与 [Tesseract.js](https://github.com/naptha/tesseract.js)：PDF 解析/渲染与图像 OCR 的不同边界。
- [ExcelJS README](https://github.com/exceljs/exceljs/blob/master/README.md)：工作簿读取及值/公式处理。

依赖是否满足 OEY 模型与平台要求，要在对应阶段实际验证。
