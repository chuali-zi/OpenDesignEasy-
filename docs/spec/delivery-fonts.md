# 交付字体证据与渲染器

2026-10-16，从远端 `codex/r6-cloud-delivery` 的 `191e38a8f38e85a18b51516da99bc680745a6108` 接续。范围为 Docs、Deck/PPT、Web 的交付检查和既有定位/编辑/重检闭环，没有增加其他交付包功能。

## 用户能看到什么

交付检查新增字体表，区分浏览器投影中的声明字体、字重/斜体、当前检查服务宿主的家族可用性，以及 Chromium 实际绘制文字的字体家族和字形数量。报告还记录 PostScript 名和浏览器版本；不把 CSS `font-family` 或 `document.fonts.check()` 当成实际用字证据。

Linux 通过 `fc-list` 的准确家族名及别名查询可用性，不使用会自动回退的 `fc-match` 判断安装。非 Linux 或目录查询失败显示可用性未知。已发现家族不保证拥有全部字形/字重；粗体可能由浏览器合成，CJK 与拉丁文字也可能分别使用不同字体。首选家族在宿主未发现，或实际字形与首选家族不同，会产生可定位提醒。通用家族如 `system-ui` 明确显示随设备解析，不把其解析结果当成缺字体。

检查针对当前保存修订生成离线浏览器投影，CDP `CSS.getPlatformFontsForNode` 测量文字。继承样式、富文本覆盖、正文/页眉/页脚、Deck 对象与 Web 节点沿用真实 HTML/SVG 生产函数。等待实际绘制后取字形证据；对未绘制的片段滚动到视口后再测，仍无字形则明确未验证。默认 Doc A4/黑色正文和黑色粗体、Deck 16:9、Web 1280×900 视口保持现有行为，不替换用户字体或改动设计状态。

提醒沿用已有位置解析及版本守卫：定位不提交命令，人工修改字体进入统一撤销历史；关闭重开重新检查，过期报告禁止定位与交付。重复点击、取消和连接断开不产生重复设计修改，检查浏览器在结束或取消时关闭。

## 渲染器与限制

检查时显示“本次导出将使用”，只有实际产物成功生成才在报告和下载后的界面显示“本次已生成”。DOCX 使用 docx、PPTX 使用 PptxGenJS 生成 OOXML，这两步不是文字渲染或 Office 打开验收。PDF/PNG 使用实际选择的 Chromium；配置本地 DOCX 渲染器的 Doc PDF 则显示 LibreOffice。源码和网页交付显示生产路径，并保留最终浏览器/设备依赖。

字体实测只证明当前检查宿主的 Chromium 投影。它不证明 Windows 缺少相同字体，不证明 Word、PowerPoint、LibreOffice 的实际用字，也不保证这些软件的换行/分页相同。native-app 检查仍为未运行。原生文件保留声明字体，检查不自动将其改为云端字体。

字体检查不执行受管脚本、不加载外部字体/图片/网络资源；Web 只测桌面默认视口，不遍历其他断点、伪元素、交互状态或自定义组件。最多测量 256 个可见文字片段，总预算 20 秒；浏览器/资源/受管组件限制或超限显式显示覆盖不完整，并给出未验证提醒。表中样本文字最多显示前 64 个 Unicode 码点，字形数量来自该片段实际绘制结果，不是字符数、全字库覆盖率或缺字率。实测不验证字符语义、遮挡、审美或完整分页。

## 验证与证据

`packages/media/test/delivery-fonts.test.ts` 使用固定中文与中英混排，验证实际字形回退、家族别名、通用字体、目录未知、富文本覆盖、页脚/对象位置、原生 OOXML 仍保留声明、隐藏对象、覆盖上限、受管组件未测量和取消。runtime/HTTP 继续核对修订、摘要和生成前后的渲染器状态。

`apps/web/e2e/delivery-fonts.spec.ts` 从真实界面定位缺字体片段，选择本机已有 Noto Sans CJK SC，撤销/重做、重开、重复检查及下载，核对修订/产物 SHA256；三媒介均确认修复后的实测字形为该字体。旧定位测试中与字体无关的 Deck 夹具显式声明已有字体，避免把字体提醒与待完成文案提醒混为一项。

本机 Chromium PDF 会把部分汉字提取成兼容部首码点（如 `⽂`、`⽆`），并拆分文字片段。旧 A4 用例现在按实际字号聚合文字，语义断言使用 NFKC；保存的原始 PDF 文字/字号指标不归一化，不把这种匹配写成 Unicode 无损提取或 Office 验收。

截图和同修订原生文件/报告生成在 `.tmp/evidence/font-delivery`，审核副本冻结在独立目录，Library 上传状态以本轮交付结果为准。本轮没有安装字体、调用收费模型或运行 Microsoft Office；Linux 浏览器实测不能作为 Windows Office 证据。

最终验证：Node 179 项中 176 通过、0 失败、3 跳过（本容器没有 LibreOffice，未运行重复页眉/奇偶分页/原生行内图像的三个测试）；Chromium 完整 44/44 通过；类型检查、核心 CLI/worker 构建、Web production 构建通过。早期绘制时序和旧 PDF 字符断言的失败日志保留，不能用最终成功改写其历史。字体、修订及产物摘要按本轮实际报告验证；目标 Windows Office 仍未复验。
