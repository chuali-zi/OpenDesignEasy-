## 验证的问题与用户流程

原交付面板能显示“附录 · 页脚”的待完成文案，报告已有 sectionId/part/nodeId，但用户需要关闭报告后手动寻找。浏览器最小用例在原起点实际失败，保留截图与日志。

现在有可靠位置的问题显示“定位问题”：关闭报告，切到对应章节/页/路由并选中问题位置。用户继续使用既有属性、富文本和统一文档命令修改，重新检查后下载同一修订的交付包。定位返回重检保留原先选择的交付格式；显式关闭结束这次返回流程。正常纸张、字号、配色、幻灯片和浏览器视口规则照常生效。

- Doc：定位到明确章节的正文、页眉或页脚，以及其中稳定 ID 对应的块/行内对象。文字定位设置光标，原子对象使用原生选区；不会改写文案。
- Deck：切到所属页，选择对象；组内对象进入相应组上下文，表格内部问题定位到唯一对应表格。锁定对象只读选择，保留锁定。
- Web：切到相应路由和元素；等当前修订/路由的 iframe 实际载入后滚动到元素，使用既有选中反馈与属性面板。
- 位置缺失、隐藏、跨页不匹配或对应多个对象时不猜测；定位按钮禁用。缺失素材等没有编辑器位置的问题仍需按报告处理。

## 状态与版本保护

请求是临时视图状态，不是文档命令，不进入历史，不代表用户接受检查或视觉效果。App 在跳转前重新核对 documentId/kind/revision，编辑器再核对当前快照；旧报告过期时禁用定位与交付。已有实际修改、撤销/重做仍走同一份文档命令和历史。

定位焦点请求首次完成后消费；后续手工切换正文/页脚、选择其他对象或重新打开区域，不重放旧请求抢焦点。此问题曾在补充浏览器用例中复现并修复，失败记录保留。

取消、关闭与检查故障不修改作品。定位之后的真实编辑会让旧修订交付请求失效；服务器原有的交付重新检查/冻结素材/产物摘要保护继续生效。已有待保存编辑和草稿使用编辑器原有保存/恢复路径，定位不清洗其他人工内容。
