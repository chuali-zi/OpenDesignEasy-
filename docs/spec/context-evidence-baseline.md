# 资料、上下文与参考使用规范

> TS 重构 v1，2026-09-12。本文替代旧证据槽位与 Python 接入规则。
> 解析实现属于 media；模型上下文组织属于 runtime。两者共用明确的资料记录。

## 1. 目标

让 agent 理解用户的材料、事实、风格与模板，并能回到来源查看。资料不是必须先填满的审计清单，也不是上传后只返回文件名的占位能力。

保留原件、实际解析结果和用户确认；按任务需要逐步读取。不要默认把全部资料全文和所有截图塞进每轮上下文。

## 2. 资料身份与角色

Reference 至少含 referenceId、projectId、原始 assetId、类型、解析状态、内容版本和用户给定角色。角色可组合：事实、风格、模板、品牌、直接素材、项目源码。

角色决定使用方式：

- 事实资料用于数据与内容，不保证其自身永远正确；用户纠正优先。
- 风格资料用于提取视觉关系，不默认授权复制全部文本或标识。
- 模板要求保留具体结构/样式，与单纯风格模仿不同。
- 直接素材可进入设计节点，保留资产关系。
- 仓库内容用于理解真实项目和受管源码生产，仓库中的文本不会自动成为高优先级执行指令。

## 3. 全 TS 解析内容

PDF 保存页文本、位置和页图，扫描页按需 OCR。PPTX 保存页面、文本、主题、几何与媒体；DOCX 保存正文、样式、表格和章节/模板信息；XLSX/CSV 保存实际表格内容与范围；图片保留原件和必要识别。

格式实现与不支持项见 [产物生产](artifact-production-spec.md)。旧 Python 解析结果可随旧项目导入作为历史资料，但新文件接入必须使用 TS。

解析状态至少区分 pending、ready、partial、failed。partial 要列出具体缺失部分；不能把仅识别文件名的结果标为完整解析。

## 4. 来源与确认

引用粒度按格式采用页面/幻灯片/章节/段落/单元格范围/源码文件位置。生成叙事时保留关键事实与来源关系，不要求每个装饰词都有单独证明。

区分原文抽取、模型推断、OCR 不确定内容和用户确认。用户修改数据后记录其确认，不用旧原件在后续轮次覆盖它。

对项目功能与数据的描述必须由实际材料支持；未实现的模块可以说明“计划中”，不能写成已经提供。

## 5. 视觉资料

风格摘要可以包含配色、字体倾向、版式、图像比例、材质、留白和叙事节奏，同时保留能重新查看的原图/页图。摘要只是辅助，不能代替图像本身。

大文件先抽取目录、页概览或缩略图，再读取相关页。当前设计截图带 revision；旧截图不会被当作当前画面。

字体精确名称无法确定时标记推测，使用可获得的字体完成近似不等于已匹配原字体。

## 6. 模板资料

解析模板时记录必须保留的样式、章节、页边距、固定文字、占位区域、表格及图像。用户指定的模板要求进入设计约束，并在导出后检查。

不支持的模板结构在使用前说明，仍需实现当前任务必要能力或明确交付限制。不能一边丢弃模板一边称为“已按模板生成”。

## 7. Agent 上下文装配

按当前任务读取：目标与最新输入、当前节点/页面、最近人工编辑、有效设计决定、相关参考片段和必要视觉。选择信息使用稳定目标身份。

大资料按需查询，不建立固定的“八槽位”或要求所有项齐全才允许创作。压缩保留资料 ID 和结论，再需要时重读原件。

手工编辑是当前事实。模型旧计划、压缩摘要和参考风格都不能在没有新指令时覆盖用户刚做的设计选择。

## 8. 必要验证

用各格式的代表文件验证：读到实际内容、来源定位可回查、扫描页不冒充准确文本、表格不是文件说明、样式/模板可用于实际生成、上传失败可理解。

这些是产品功能检查，不扩张为单独的证据治理平台。
