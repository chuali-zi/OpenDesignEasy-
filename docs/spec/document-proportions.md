# 默认文档样式与媒介比例

2026-10-14，用户正在验收并要求正常纸张、幻灯片与浏览器比例，以及无模板 Docs 的黑色文字层级。本轮是针对性修复，不能写成审美或 Word 已通过。

## 实际默认值

- 新建无模板 Doc：A4 纵向 210 × 297 mm，模型为 793.7008 × 1122.5197 px（96 px/in）；四边 96 px = 25.4 mm，正文栏约 159.2 × 246.2 mm。现有模板、显式纸张和颜色仍保留，不进行颜色清洗或图片重着色。
- 新建 Doc 记录 Normal 和 Heading1–6 样式；正文 16px = 12pt，行高 24px = 18pt，段后 8px。标题 1/2/3 为 24/20/18px（18/15/13.5pt）、黑色加粗，行高 32/28/26px，段前 16px、段后 8px，标题与下段保持相邻。编辑器、HTML、DOCX 读取同一默认样式；显式样式/文字 mark 优先。
- 无模板浮动文字框默认白底、黑色边线/文字。模板及已保存对象的显式 fill/stroke/color 保留。表格单元格默认内边距 8px，正文图片保持原始比例并应位于正文栏内。
- Doc 默认显示 100%；纸张/正文尺寸和显示缩放明确列出。缩放 50/100/125% 均不修改纸张、正文、样式或修订。自定义纸张准确显示实际尺寸，不能一律标为 A4。
- Deck 保持已有默认 1280 × 720（16:9）；指定 4:3 等尺寸照常保留。PPTX 使用 logical px/96 转英寸，PDF 与 PNG 沿用页面尺寸；不改成 A4。编辑器百分比显示实际 stageScale（包括适应画布的比例），避免把相对适应视图的 100% 误称为真实像素 100%。
- Web 预览默认桌面 1280 × 900px，新增窄屏 390 × 844px 和明确高度；真实 iframe 视口独立于编辑区高度和显示缩放。编辑器、静态页面及 React 源码共用 16px/1.5 的基础字体，显式组件/CSS 样式优先。
- Web PDF 原来写死 A4/16mm 边距，本轮改为实际渲染视口（默认 1280 × 900px）、无附加纸张边距和 screen 媒体布局；可通过现有 width/height 选项指定视口，长内容仍可能分页。PDF 不是具有唯一比例的媒介。

## Agent 与真实导出检查

规则进入 Pi 实际 system prompt，工具 schema 的 Doc 示例使用黑色。提醒无模板 Doc 少用非黑色文字、避免浅色文字，靠加粗/字号/留白建立层级；图片/表格适应实际正文宽度，保留图片比例。Deck 按正常幻灯片尺度，Web 在桌面与窄屏、100% 显示检查；现有模板和显式要求优先。只以离线 faux provider 验证实际上下文和工具返回，本轮没有调用收费模型。

同一合成 Doc 的 100% 浏览器截图、DOCX 和 LibreOffice PDF 使用同一 documentId/revision/snapshot hash。核查实际 A4、字号、正文栏、表格/插图占比及缩放；原生 PDF 独立核查页数、页面尺寸与提取文字字号。浏览器与原生 PDF 均实际查看，不能仅凭字段/HTTP 成功断言视觉正确。

原生查看发现固定正文行高裁切高于文字行的行内图片；已将含行内图片的段落使用最小行高而非精确行高。新原生回归渲染 360 × 180px 黑色合成矩形，在 96 dpi PDF 页面中检测实际可见像素宽高/面积，能抓住“图片对象存在但被裁切”的问题。默认表格单元格内边距也与编辑器统一。

100% 纸页使旧 PDF 面板占用过多编辑空间，本轮限制嵌入 PDF 预览高度，保留可编辑正文滚动区域；这只改变视图。测试按实际显示比例核查浮动对象拖动，避免继续假设旧的 80% 默认缩放。

Web 审核截图来自同一修订的独立浏览器页面，使用真实 1280 × 900 / 390 × 844 视口与 100% 显示，避免编辑器侧栏裁切；匹配导出 HTML/PDF。记录正文 16px、行高 24px、标题尺寸、控件高度、内容栏及横向溢出。Deck 示例记录规范尺寸、文字字号与同一修订导出，不能将编辑器适应画布的显示当作另一纸张大小。

## 边界与复现

浏览器与 Office 的字体塑形、换行、段落/表格分页和页眉页脚位置仍可能不同；相同纸张、字号与夹具不是逐像素一致的承诺。Chromium/OOXML 对物理尺寸存在细小取整，报告保存实际测量值。模板保留与可编辑导入的既有有限范围不扩张；实际 Microsoft Word/字体环境与本轮审美仍待用户审核。

复现环境：Node 24.21.0、预置 Chromium、原生 LibreOffice；运行 npm test、npm run build、npm run build:web、npm run test:web。浏览器使用 OEY_BROWSER_EXECUTABLE；原生测试使用 OEY_TEST_DOCX_RENDERER，图片可见面积测试还使用 OEY_TEST_PDF_RASTERIZER 指向 pdftoppm；Doc PDF 生产使用 OEY_DOCX_RENDERER。不需要模型凭据。

证据目录：oey-cloud-evidence/r5-proportions。保留首轮旧构建、旧缩放假设、预览点击和行内图片裁切的真实失败记录；最终报告以最后完成的回归结果为准。审核产物另存稳定副本，后续运行不覆盖 Library 已保存文件。

最终回归：Node 151/151（无跳过）、Chromium 33/33、类型检查及核心/网页构建通过。新原生图片测试实测黑色区域 360 × 181px、65160 个像素；1px 的栅格化取整不等于图片裁切。保留同夹具的 A4 原生 96dpi 图片，实际查看确认插图完整。照片对照仍能看到局部中文换行差异：关于图片比例的段落在浏览器中为两行，LibreOffice 中为一行；相同纸张/字号不是逐像素排版一致，目标 Word 仍待验。本轮没有收费模型请求。
