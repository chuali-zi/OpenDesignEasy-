# 设计智能规范

> TS 重构 v1，2026-09-12。设计能力建立在可直接编辑的文档和 Pi 工具循环上。
> 本文规定设计行为，不重新定义执行引擎。

## 1. 目标

Agent 能和用户共同思考、形成视觉方向、制作作品、观察结果并持续修改。输出需要内容结构、视觉层级和适合用途的表达；交互能力不能退化成把一句话包装成固定 PPT 流水线。

用户可以只讨论、只修改局部、要求直接交付，也可以先探索方向。系统识别这些意图，选择合适动作，不强制同一套步骤。

## 2. 保留与改变

保留旧项目有价值的设计思想：以用户用途为先、参考资料参与推理、图像是实际设计素材、真实渲染后检查、使用者选择可继续影响结果、三个媒介均可交付。

改变旧实现的限制：设计不再由完整 HTML 写入或一次 set_artifact 决定；结构化文档从创作起存在，人工修改成为下一轮设计上下文的一部分，模型只修改需要变化的节点。

不保留固定视觉双主题、固定页数、固定卡片构成或固定工具顺序。结构化模型用于编辑与生产，不用于压缩创作空间。

## 3. 理解与决策

理解用途、受众、媒介、内容与约束；资料不足时区分：

- 可自行判断的视觉实现，例如间距、排版、图像裁切。
- 影响整体方向但可声明假设的选择，例如无品牌材料时的初始风格。
- 需要用户提供的事实、重大方向选择或外部授权。

问题应少而具体。用户已经确认过的选择记录为 DesignDecision，后续不会每次重问。用户手工调整和锁定也是明确设计信号。

## 4. 探索与创作

有价值的方向差异应体现在构图、字体、色彩、素材、内容叙事和空间关系。不能只换配色就称为不同方案。

草图与素材探索可使用图片、说明或临时预览；选定并进入编辑的成果要由真实节点表示。候选具有独立身份，选择一个方向不会覆盖其他已保存作品。

初始生成通过文档操作创建结构；渐进提交可展示页面完成情况。Agent 不必一次填满全文件才能获得反馈。

## 5. 连续共同编辑

每次修改先确定目标与用户想保留的部分。用户选中对象时使用稳定 nodeId 和当前修订，说明文字只辅助理解。

人工移动后的布局优先于旧模型计划。Agent 可以解释建议，但不能因“优化”自动恢复旧坐标。用户明确要求整体重新设计时，才在该范围内调整已确认内容。

局部修改应能保留其他页面和元素；通过重建全文实现一个改字请求不符合要求。较大重排可以分批完成，但每批可恢复、可见且边界清楚。

## 6. 素材、风格与事实

资料可分别承担事实、视觉参考、模板、品牌和直接素材等角色。Agent 根据角色使用信息，不把参考中的每个字都复制进产物，也不把图中的装饰文字当作确认事实。

生图用于照片、插画和质感等适用视觉内容。精确公式、数据图、流程、品牌名称、UI 文本应使用可编辑对象或可验证的结构化表达。

模仿风格应提取构图、节奏、字体倾向、材质与色彩关系，并结合用户内容重新设计。模板任务则优先匹配用户指定结构和样式；两者不能混淆。

## 7. 看见并修正

Agent 查看当前修订的真实渲染，结合结构数据检查溢出、间距、对齐、裁切、对比与内容完整性。视觉问题回到对应对象操作修复，而不是只在总结中描述。

视觉检查可以在重要布局变化和最终交付时发生，不要求每次改一个字都截图多轮评分。用户已明确审美偏好时，不用泛化评分推翻选择。

## 8. 三媒介的设计质量

| 媒介 | 必须关注 |
|---|---|
| Web | 内容架构、响应式、真实导航/交互、可访问语义、素材与页面节奏 |
| Deck | 叙事顺序、单页层级、跨页一致性、图表与公式准确性、演讲可读性 |
| Doc | 章节、正文可读性、样式体系、表格与插图、模板、分页和事实出处 |

不能用共同的 HTML 截图掩盖某媒介缺少原生编辑和生产路径。对应生产结果按 [产物规范](artifact-production-spec.md)检查。

## 9. 验证与完成

必要例子包括：模糊需求的方向探索、用户选择后的继续制作、手动改版后的局部续改、参考模板报告、含公式和数据的教学演示、带真实交互的 Web 项目。

完成意味着用户的当前请求完成；没有完成的页面、失败的图片生成、导出格式限制要明确呈现。一次请求完成不等于整个产品重构完成。
