# R5 Doc 浮动对象与原生锚点

2026-10-13。浮动图片、矩形/椭圆与文字框是正文段落中的稳定 ID 原子节点；人工与 Pi/CLI 仍提交同一 `doc.text.apply`，没有额外 DOM 真源。x 使用正文栏逻辑像素，y 相对所属段落顶部；尺寸、旋转和环绕存入文档。当前明确支持 none 与 topBottom，其他 Word 位置/环绕方式拒绝导入。

Web 可插入文字框/图形、选择将图片插入为浮动对象，拖拽、旋转后按局部坐标缩放、编辑坐标/尺寸/文字/颜色、锁定及撤销重做。手势只预演 DOM，放手提交一次步骤；Escape、取消、远端属性变化或不可编辑状态终止预演。尚未保存的正文先提交，再接受对象手势。锁定保护由 Kernel 执行，禁止移动、删除和换段落；只解锁不能夹带几何修改。正文变化及原段落重排保留锚点身份，保存重开保持几何。

DOCX 生成真实 wp:anchor 与 DrawingML 图片/可编辑形状，采用 COLUMN/PARAGRAPH EMU 偏移；导入可还原有限锚点、旋转、形状文字/颜色与 PNG/JPEG 原件。Runtime 同时重映射行内及浮动图片资产 ID。原件与模板字节保留路径不变；不支持的裁切、翻转、复杂形状、其他相对位置/环绕应明确拒绝。HTML/PNG/PDF 与编辑器使用旋转外框预留上下空间。

实际 LibreOffice 打开合成 DOCX，中文文字框、旋转、绿色背景/描边与正文均可见，证据在 `oey-cloud-evidence/r5-doc-floating`。实际 LibreOffice 的文字框内容仍显示为水平文字；旋转文字与 Word 的最终一致性待复核，不能据此声称像素一致。Microsoft Word 未验证，正文流编辑仍不代称完整 Word 分页或审美通过。此切片没有新增真实模型请求。
